# 지표 정의서 `metrics-v1`

AI ↔ 프런트 ↔ 백엔드의 약속 문서. 계산은 **모두 부모 폰의 브라우저 안에서** 끝나고, 서버에는 아래 JSON만 간다.

## 1. 입력과 전처리

| 항목 | 값 |
|---|---|
| 입력 | 폰으로 찍은 영상 1개(권장 1~3분, 최대 30분). 폰을 세워 두고 부모와 아이가 함께 화면에 나오게 촬영 |
| 파일 크기 | 500MB 이하(`navigator.deviceMemory` 가 2GB 이하인 기기는 200MB). 소리를 읽는 `decodeAudioData` 가 파일 전체를 한 번에 받아 파일 크기만큼 메모리를 쓰기 때문. 넘으면 `AnalysisError`(실제 상한 MB 를 알려 주는 문구). 메모리를 얻지 못하면 메모리 안내 문구의 `AnalysisError`. 계산 방법과는 무관해 `specVersion`·`modelVersion` 은 그대로 |
| 영상 프레임 | 0.5초 간격(2fps) 샘플링, 긴 변 640px로 축소 후 분석 |
| 분석 길이 | 영상 길이 10초 이상 30분 이하만 분석. `analyzedSeconds` = 영상 길이(소수 1자리) |
| 자세 모델 | MediaPipe Pose Landmarker **lite**(float16, `@mediapipe/tasks-vision` 0.10.35), `numPoses=2`, VIDEO 모드, 검출·존재·추적 신뢰도 0.5, GPU 실패 시 CPU |
| 프레임 타임스탬프 | 페이지당 모델 인스턴스 1개를 다시 쓰므로, 타임스탬프(ms)는 페이지 안에서 계속 커진다: 분석마다 직전 값 + 1 + 10,000ms(분석 사이 간격)에서 시작해 + 영상 안 위치(ms), 항상 직전 값보다 큼 |
| 오디오 | 영상 파일을 `OfflineAudioContext`(1채널, 16kHz)의 `decodeAudioData`로 디코딩(16kHz로 맞춰짐) → 채널 평균 → 모노 |
| 오디오 프레임 | 40ms 창(640샘플), 20ms 이동(320샘플). 프레임마다 RMS(dB = 20·log10(RMS + 1e-9)) |
| 기본 주파수(F0) | 정규화 자기상관, 탐색 범위 75~1000Hz(지연 16~214샘플). 최고 상관값 < 0.5면 F0 없음. 옥타브 아래로 잘못 잡지 않도록 최고값의 90% 이상인 첫 봉우리의 지연을 씀 |
| 바닥 dB | 모든 프레임 dB의 하위 20% 분위값 |
| 소리 있는 프레임 | 프레임 dB > 바닥 dB + 10dB 이고 F0가 있음 |
| 화자 구분(추정) | F0 ≥ 280Hz → 아이, 85~255Hz → 어른, 그 밖(85Hz 미만, 255~280Hz) → 구분 안 함 |
| 구간 묶기 | 같은 화자 프레임을 시간순으로 이어 붙인다. 앞 프레임 시작과 다음 프레임 시작의 간격이 0.2초 + 반 프레임(10ms)을 넘으면 끊음. 구간 = 첫 프레임 시작 ~ 마지막 프레임 시작 + 40ms. 0.2초 미만 구간은 버림 |

> 화자 구분은 음높이만 쓰는 추정이다. 목소리가 높은 어른이나 낮은 아이는 섞일 수 있다. 그래서 이 지표는 **같은 가정의 시간에 따른 변화**를 보는 용도로만 쓰고, 다른 가정과 비교하지 않는다.

## 2. 지표 3개

### ① 함께 노는 시간 `jointPlaySeconds`

| 항목 | 정의 |
|---|---|
| 의미 | 부모와 아이가 한 화면에 가까이 함께 있었던 시간 |
| 단위 | 초(소수 1자리) |
| 사람 검출 | 양 어깨가 보여야(visibility ≥ 0.3) 사람으로 셈. 양 엉덩이도 보이면 몸통 중심 = 어깨 중점과 엉덩이 중점의 가운데, 몸통 길이 = 두 중점 사이 거리 |
| 엉덩이가 화면 밖일 때 | 어깨너비(픽셀)로 어림: 몸통 중심 = 어깨 중점에서 아래로 어깨너비 × 0.6, 몸통 길이 = 어깨너비 × 1.2 |
| 계산 | 0.5초 간격 샘플 프레임(0, 0.5, 1.0 … 초, 영상 길이 ÷ 0.5 내림 개수)마다 사람 2명이 검출되고, 두 사람 몸통 중심 사이 거리 ≤ 두 사람 평균 몸통 길이 × 2.5 이면 "함께" 프레임. 한 프레임짜리 끊김(앞뒤가 함께)은 함께로 메움. 함께 프레임 수 × 0.5초(소수 1자리), `analyzedSeconds`를 넘지 않음 |
| 화면 표시 | "함께한 시간 ○분 ○초" 와 분석 길이 대비 비율 |

### ② 부모 반응 시간 `responseLatencySec`

| 항목 | 정의 |
|---|---|
| 의미 | 아이가 소리를 낸 뒤 부모 목소리가 이어지기까지 걸린 시간 |
| 단위 | 초(소수 2자리), 중앙값 |
| 아이 발화(`childBidCount`) | 아이 구간 중 길이 ≥ 300ms 인 것 (울음 구간 제외) |
| 반응(`respondedBidCount`) | 시작 시각이 (아이 발화 시작 + 0.2초) 이상, (아이 발화 끝 + 5초) 이하인 첫 어른 구간. 지연 = 어른 구간 시작 − 아이 발화 끝(음수면 0초, 즉 아이 발화 도중 시작한 경우) |
| 값 | 반응된 발화들의 지연 중앙값(짝수 개면 가운데 두 값의 평균), 10초를 넘지 않음, 소수 2자리. **반응된 발화가 3개 이상일 때만** 값을 내고, 3개 미만이면 `null`("이번 영상에선 측정이 어려웠어요") |

### ③ 울음·감정 폭발 횟수 `distressEpisodeCount`

| 항목 | 정의 |
|---|---|
| 의미 | 아이가 크게, 길게 운 횟수 |
| 단위 | 회 |
| 큰 아이 소리 프레임 | 아이 프레임(소리 있음, F0 ≥ 280Hz) 중 **그 프레임의** dB ≥ 바닥 dB + 25dB 인 것(구간 평균이 아니라 프레임마다 판단) |
| 계산 | 큰 아이 소리 프레임을 "구간 묶기"와 같은 방식으로 잇되, 프레임 시작 간격 0.5초 + 10ms까지 이어 붙이고, 길이 1.5초 이상인 구간만 남김. 시간순으로 보며 다음 구간 시작이 앞 횟수의 끝과 3초 이내면 같은 한 번으로 합침(끝을 늘림). 합친 뒤의 개수 |
| 아이 발화와의 관계 | 이렇게 센 구간과 겹치는 아이 구간은 아이 발화(②)에서 빠짐 |

## 3. 전송 JSON

`POST /api/v1/children/{childId}/interaction-records`

```json
{
  "clientRecordId": "1f0c7b1e-5a1d-4c5e-9a55-0b8f6f5f2d10",
  "recordedAt": "2026-11-06T09:30:00Z",
  "analyzedSeconds": 182.5,
  "jointPlaySeconds": 121.0,
  "responseLatencySec": 1.42,
  "childBidCount": 14,
  "respondedBidCount": 11,
  "distressEpisodeCount": 1,
  "modelVersion": "pose_landmarker_lite@0.10.35+audio-heuristic-1",
  "specVersion": "metrics-v1"
}
```

| 필드 | 타입 | 규칙 |
|---|---|---|
| clientRecordId | UUID | 기기에서 생성. 재전송 시 같은 값 |
| recordedAt | ISO-8601 | 영상 파일의 수정 시각(없으면 분석 시각). 미래 불가 |
| analyzedSeconds | number | 10 ~ 1800 |
| jointPlaySeconds | number | 0 ~ analyzedSeconds |
| responseLatencySec | number \| null | 0 ~ 10 |
| childBidCount | int | 0 ~ 2000 |
| respondedBidCount | int | 0 ~ childBidCount |
| distressEpisodeCount | int | 0 ~ 200 |
| modelVersion | string | 1~100자. 현재 값은 `MODEL_VERSION`(`src/analyzeVideo.ts`) = `pose_landmarker_lite@0.10.35+audio-heuristic-1` |
| specVersion | string | `metrics-v1` |

## 4. 버전 규칙

계산 방법이 바뀌면 `specVersion`을 올리고(`metrics-v2`), 백엔드 지원 목록에 추가한다. 서로 다른 버전의 값은 변화 추이 계산에서 섞지 않는다(기준값은 같은 `specVersion` 기록만 사용).

## 5. 사람이 잰 값과 비교하기 (내부용)

팀원 연출 영상 10개 이상에서 사람이 스톱워치로 잰 값과 비교해 차이를 기록한다(`eval/`, 여러 영상을 한 번에 분석). 결과는 내부 개선용이며, 앱·발표 자료에 "○○% 맞음" 같은 퍼센트 수치로 쓰지 않는다.
